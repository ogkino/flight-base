# CRUD Admin Development Skill

Use this skill when creating a **standard CRUD admin module** (list page with search, add/edit/delete). This is the configuration-driven approach — you write PHP config and a controller; the frontend is auto-generated by `crud-renderer.js`.

**For custom UI pages (charts, wizards, complex forms), use the `view-admin` skill instead.**
**For standalone API endpoints without CRUD pages, use the `api-development` skill instead.**

## The 4-Step Process

Every new CRUD module follows exactly 4 steps:

```
1. Create Controller (business logic)
2. Add CrudConfig (UI definition)
3. Register Routes (in bootstrap.php)
4. Add Menu Entry (in CrudConfig::getMenus())
```

---

## Step 1: Create Controller

File: `app/api/admin/XxxController.php`
Namespace: `App\api\admin`

Standard CRUD methods — exactly 4 methods needed:

```php
<?php
namespace App\api\admin;

use App\middleware\AuthMiddleware;

class XxxController
{
    public static function list()
    {
        AuthMiddleware::checkAdmin();
        checkPermission('products', 'list');

        $db = db();
        $page  = max(1, (int)getQuery('page', 1));
        $limit = max(1, (int)getQuery('limit', 10));
        $keyword = getQuery('keyword', '');

        $where = [];
        if ($keyword) {
            $where['name[~]'] = $keyword;
        }

        $count = $db->count('products', $where);
        $data  = $db->select('products', '*', array_merge($where, [
            'LIMIT' => [($page - 1) * $limit, $limit],
            'ORDER' => ['id' => 'DESC']
        ]));

        layuiTable($data, $count);
    }

    public static function create()
    {
        AuthMiddleware::checkAdmin();
        checkPermission('products', 'create');

        $db = db();
        $db->insert('products', [
            'name'    => getPost('name'),
            'price'   => getPost('price'),
            'status'  => getPost('status', 1),
        ]);
        success(['id' => $db->id()], '创建成功');
    }

    public static function update($id)
    {
        AuthMiddleware::checkAdmin();
        checkPermission('products', 'update');

        $db = db();
        $data = [
            'name'   => getPost('name'),
            'price'  => getPost('price'),
            'status' => getPost('status', 1),
        ];

        // Password-type fields: skip if empty on edit
        $password = getPost('password', '');
        if ($password !== '') {
            $data['password'] = hashPassword($password);
        }

        $db->update('products', $data, ['id' => $id]);
        success([], '更新成功');
    }

    public static function delete($id)
    {
        AuthMiddleware::checkAdmin();
        checkPermission('products', 'delete');

        db()->delete('products', ['id' => $id]);
        success([], '删除成功');
    }
}
```

### Key patterns in controllers:
- `permission` strings in `checkPermission()` match the module key in permissions JSON (e.g., `'products'`)
- Password fields: check if empty string on edit before hashing (leave unchanged if not provided)
- Use `layuiTable($data, $count)` for list endpoints (Layui needs `count` for pagination)

### CrudConfig Structure Reference

| Section | Required | Purpose |
|---------|----------|---------|
| `page` | Yes | `title`, `icon`, `page` (menu key) |
| `table` | Yes | `url` (data endpoint), `cols` (columns) |
| `actions` | Yes | Row-level action buttons (edit, delete, custom) |
| `search` | No | Search fields above the table |
| `toolbar` | No | Buttons in the toolbar (add, export, etc.) |
| `form` | Yes | Fields for the add/edit modal form |
| `api` | Yes | Endpoint URLs for CRUD operations |
| `tips` | No | Custom tip messages (e.g., delete warning) |

### Available Field Types

`input`, `password`, `textarea`, `editor` (rich text), `number`, `radio`, `select`, `switch`, `date`, `datetime`, `time`, `timestamp`, `upload`, `image`, `color`, `slider`, `permissions`

### Dictionary-backed fields

For `select`/`radio`/`checkbox`/table `status`-like fields whose options should be centrally managed (not hardcoded per-module), use the built-in data dictionary instead of a static `options` array — see `docs/DICT.md`.

```php
// Static options generated from a dict type (regenerated on every request, no caching issues):
['type' => 'select', 'name' => 'status', 'label' => '状态',
 'options' => array_map(fn($d) => ['value' => $d['value'], 'label' => $d['label'], 'color' => $d['color']], dict('common_status'))],

// OR fully dynamic (dict changes reflect immediately without touching CrudConfig):
['type' => 'select', 'name' => 'status', 'label' => '状态',
 'url' => '/api/admin/dict/data/options?type=common_status', 'valueField' => 'value', 'labelField' => 'label'],
```

In controllers, use `dictLabel('common_status', $row['status'])` to format list output. Manage dict types/data under 系统管理 → 字典类型 / 字典数据 in the admin panel.

### Multi-language modules

If the project has multi-language admin enabled (see `docs/I18N.md`), add a `{key}_en` sibling next to any user-facing text key (`title`, `label`, `text`, `placeholder`, `tip`, menu item `name`, etc.) instead of hardcoding only Chinese:

```php
['field' => 'name', 'title' => '名称', 'title_en' => 'Name'],
['type' => 'input', 'name' => 'name', 'label' => '名称', 'label_en' => 'Name'],
```

`ConfigController` automatically resolves these via `localizeConfig()` based on the current locale and strips the `_en` keys before the response is sent — no other changes needed. This is a hand-written convention only; the visual CRUD designer does not support editing these fields. Do not add this unless the project actually needs multi-language.

## Step 3: Register Routes

File: `app/bootstrap.php`

Add routes in the admin section (after existing CRUD routes):

```php
// 商品管理
Flight::route('GET /api/admin/products', function () {
    \App\api\admin\ProductController::list();
});

Flight::route('POST /api/admin/product', function () {
    \App\api\admin\ProductController::create();
});

Flight::route('POST /api/admin/product/@id', function ($id) {
    \App\api\admin\ProductController::update($id);
});

Flight::route('DELETE /api/admin/product/@id', function ($id) {
    \App\api\admin\ProductController::delete($id);
});
```

**URL convention:** plural for list (`/api/admin/products`), singular for single-item ops (`/api/admin/product`).

## Step 4: Add Menu Entry

File: `app/config/CrudConfig.php` → `getMenus()` method

Add to the appropriate menu group, or create a new group:

```php
public static function getMenus()
{
    return [
        // ... existing groups ...
        '商品管理' => [
            'icon' => 'layui-icon-cart',
            'items' => [
                [
                    'name' => '商品管理',
                    'page' => 'products',
                    'icon' => 'layui-icon-cart',
                ],
            ],
        ],
    ];
}
```

The `page` value must match the `page.page` value in your CrudConfig method.

## Permission Integration

Permissions are JSON-based, stored in `og_admin.permissions`. The module key used in `checkPermission('products', 'create')` is the **same string used as the CrudConfig method name and page value**.

Available permission actions: `list`, `create`, `update`, `delete`, `export`, `custom`

When you add a module to `CrudConfig::getMenus()`, the permission system (`getAllPermissions()`) automatically picks it up and makes it available in the admin permission configuration UI.
